Perpensum非公開パイロット · Console · English

製品ドキュメント

1回の購買を、次に使える経験として残す。

Perpensumは、買い手AIがすでに行っている購買の前後をつなぎます。判断前に分かっていたことを固定し、選んだActionを記録し、その後に観測した結果を追記します。

3-call loop

1
実行前に尋ねる
ask_purchase_adviceで、Goal、Situation、買わない選択を含むAction一式、制約、観測予定のOutcomeを固定します。Decision Engineは、根拠の範囲を限定したEvidenceを返すか、判断を控えます。
2
Choiceを記録する
record_purchase_choiceで、選んだActionを記録します。購入する場合はPurchaseの状態と証拠digestも記録します。実際の購入は、引き続き買い手自身の提供者経路で行います。
3
Outcomeを1件ずつ報告する
report_purchase_outcomeで、型付きObservationか、観測できなかった明示的な理由を追記します。別のmetricや後日の観測にも繰り返し使えます。欠測を暗黙に失敗へ変換しません。

ライフサイクルを補う保守用ツールは2つあります。withdraw_purchase_outcomeは履歴を書き換えずに無効なObservationを撤回し、get_purchase_episodeは型付きの要約を返します。

2つの中核が担う役割

CEN

Collective Experience Network

購買経験のEvidenceを蓄積する記憶層です。購買に至る因果順序、独立controlの識別情報、同意、時刻、欠測、訂正に加え、過去の経験が今回に当てはまるかを判断するための最小限の型付き文脈を保持します。

DE

Decision Engine

根拠の範囲を超えない解釈器です。その判断時点で適格だったCEN Projectionを読み、直接使えるEvidenceと弱いシグナルを分け、買い手が固定した制約を適用します。必要な条件を満たしたときだけ選好を返します。

買い手AI

最終権限

Mandate、効用、資格情報、提供者経路、実行は買い手が持ちます。Perpensumは判断材料を提供しますが、購入を代理せず、すべてに共通する目的関数にもなりません。

Decisionが返す可能性のある答え

範囲を限定した選好追加収集判断保留

選好を返すには、今回へ直接適用できるEvidence、十分な独立した支持とカバレッジ、現行の識別情報と測定法、互換性のある単位、必須制約の充足が必要です。また、まだ優れている可能性のある未検証の選択肢を無視できません。条件を満たさなければ、通常はEvidenceの追加収集か判断保留になります。

記録されたOutcome分布は、そのまま因果効果にはなりません。類推による転用、予測、方針の最適化、Contextual Banditにはそれぞれ別の判定条件があり、薄い集団だけでは有効になりません。

データ境界

送らないもの

  • 提供者または決済の資格情報
  • 生のプロンプト、入力、出力
  • 顧客記録や原文書
  • レシート本文や非公開成果物

型付きの非公開記録

  • Goal、Situation、Action一式
  • Offeringとreleaseの識別情報
  • Choiceと購買証拠のdigest
  • Outcome値または欠測理由

Collectiveでの利用

  • 参加者の明示的な同意
  • サーバー側で管理するShare Profile
  • 比較可能性とEvidenceの判定条件
  • 個人を特定しない集約された支持

Claude Codeへ接続する

CENが薄い間、参加は非公開です。承認後、Consoleへログインし、表示された参加条件へ同意して、一度だけ表示されるMCPキーを発行します。Consoleに表示された完全なコマンドをそのままコピーしてください。形式は次のとおりです。

claude mcp add --transport http --scope user perpensum \
  'https://api.perpensum.org/v1/mcp' \
  --header 'Authorization: Bearer <your key>'

キーをプロンプトへ貼ったり、Perpensumのサポートへ送ったりしないでください。Consoleが表示するのは1回だけです。新しいキーを発行すると、前のキーは無効になります。

現在の実装範囲

本番の中核機能と3-call MCP loopは稼働しています。ただし、現在実装済みの参加プロファイルはReplicate経由の構造化請求書抽出に限られます。ほかの有料モデル、API、エージェント、デジタルサービスへ、そのまますぐ接続できるという意味ではありません。対象を広げるには、Offering、release、Situation、Outcome schema、測定法、データ境界を個別に登録し、検証する必要があります。

初期のCEN Evidenceは1つの内部controlから得たもので、買い手をまたぐ信頼性はまだ示せません。最初の非公開パイロットでは、この限定プロファイルで自然な購買を3回行う、独立した買い手を1組対象にします。最良の提供者、普遍的な品質スコア、因果的な改善、価格ベンチマーク、自動購入は約束しません。

最初の買い手パイロットを読むか、hello@perpensum.orgへご連絡ください。資格情報、プロンプト、出力、購買記録、顧客データは添付しないでください。

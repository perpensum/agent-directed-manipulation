購買経路に、独立した品質検証レイヤーを置く。

仕組み

1回の購買、5段階の証拠

  1. 1
    マンデート組織が、買い手AIが動く前に予算、許可する経路、購買回数を設定します。
  2. 2
    計画と約束買い手AIが、目的、成功条件、選んだ売り手、商品、売り手の表示内容を固定します。
  3. 3
    判断Perpensumが依頼をマンデートと照合し、短命で1回限りの実行券を発行するか、購買を止めます。
  4. 4
    手元での実行と観測買い手側Gatewayが提供者を呼びます。資格情報や生の成果は買い手環境内に残せます。
  5. 5
    検証と次回行動観測結果を固定済み条件と比較し、証拠、乖離、不確実性、範囲を限定した次回購買行動を返します。

基本概念

すべての接続方法で使う用語

用語平易な意味
APQVAgentic Purchase Quality Verification。購入前に固定した買い手の意図と、提供元、取引、納品、成果について観測できた証拠を比較すること。
Mandate買い手AIへ委任された権限、予算、回数、期間、購買経路の制限。
Gateway実行前に判断を取得し、実行後に結果を観測する、買い手側の購買関門。
Adapter共通Gatewayの形式と、個別の提供者またはコマースプロトコルの形式をつなぐ小さな翻訳部品。
Control Planeホストされた方針・証拠サービス。マンデートを評価し、1回限りの実行券を発行し、範囲を限定したOutcome telemetryを受け取ります。
Evidence record1回の機械購買について、意図、判断、実行、納品、買い手観測、証拠不足、検証限界を結び付けた記録。

Gateway

購買ごとではなく、1つの信頼境界に1つ

通常、組織は信頼できる環境内にGateway runtimeを1つ導入します。複数の買い手AI profileが同じGatewayを共有しながら、それぞれの身元、割り当てられたマンデート、秘密鍵、提供者資格情報、復旧記録を分離できます。

Gatewayは、顧客のすべての購買をPerpensumが中央で代理購入するという意味ではありません。顧客の買い手AIが提供者へ到達する前に、管理された顧客側の実行地点を通すという意味です。

MCP Preview

AIエージェントにとって最短の接続方法

非公開の候補版は、Sandbox用にrun_apqv_sandbox_purchaseという1つのツールだけを公開します。資格情報や任意の購買先は受け取りません。

公開予定のコマンド — npmではまだ利用できません
claude mcp add perpensum -- npx -y @perpensum/mcp

実在の提供者から購入する場合は、Hosted Alphaから発行された認証済みGateway profileを使います。公開MCP packageが、利用者の知らないうちに支出権限を持つことはありません。

JavaScript SDK Preview

意図的に小さくしたclient

候補版は1つのmethodから始めます。最小で安定した契約が明確になってから、Production用methodを追加します。

Preview API — packageはまだ非公開です
import { PerpensumClient } from "@perpensum/sdk";

const perpensum = new PerpensumClient();
const result = await perpensum.runSandboxPurchase({
  scenario: "provider_succeeded_unusable"
});

console.log(result.verification);

公開Sandbox API

実API呼び出し、合成された実行

POST https://api.perpensum.org/v1/sandboxは、scenarioという1項目だけを受け取ります。実在の提供者を指定できず、資金を動かさず、データも保存しないため、認証は不要です。

Request
{ "scenario": "usable" }

選べるscenarioはusable、provider_succeeded_unusable、insufficient_evidenceです。

応答には、範囲を限定したマンデート、購入依頼、許可条件、合成された納品、項目ごとの検証、証拠記録、次回購買行動が含まれます。Browser Quickstartはこれを使って各段階の裏側を表示します。

安全境界

手元に残すものと、証拠になるもの

買い手環境Hosted Control Plane
提供者API token、カード情報、wallet secret購買目的と、購入前に固定した成功条件
設定に応じて、生のprompt、入力、出力選んだ売り手、商品、表示された約束、価格、購買経路
AIごとの秘密鍵と実行復旧記録マンデート判断と、範囲を限定した買い手側の成果観測

公開Sandboxはどちらの情報も保存しません。Hosted Alphaは範囲を限定した証拠を保存しますが、提供者資格情報を中央保存しません。

現在の限界

v0が主張しないこと

  • その購買が絶対的に良かったかは判定しません。
  • 乖離や失敗だけから不正と断定しません。
  • 買い手横断の価格基準や市場全体の最適化はまだ提供しません。
  • 最初の市場は、機械検証可能なデジタル成果物とサービスです。物理商品は対象外です。
  • 意味内容の深い品質検査は目的ごとに異なります。構造が正しい成果でも、内容が不正確な場合があります。
  • 公開SDKとMCP packageの名称、ライセンス、公開repositoryはまだ確定していません。

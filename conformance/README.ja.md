# 適合性テスト — エージェント向け誘導の定義 v0.1

**基準は、誰が測っても同じ判定になって初めて基準になります。**
この一式は、あなたの実装がこの定義と同じ判定に到達するかを確かめるためのものです。

English: [`README.md`](README.md)（こちらが正）

## 使い方

```bash
node run.mjs <あなたの実装のパス>
```

実装は次のいずれかの形の関数を export してください（`default` / `scan` / `scanHtml` のいずれか）。

```js
(html)         => ({ findings: [{ severity: "info" | "warn" | "high" }] })
({ html })     => ({ findings: [{ severity: "info" | "warn" | "high" }] })
```

**どちらでも構いません。** 引数の受け取り方は定義の一部ではないため、
ランナーが両方を試して通ったほうを使います。

**重大度は findings の最大値で比較します。** findings の並び順も定義の一部ではありません。

依存パッケージはありません。Node 18以上で動きます。
終了コードは、全一致で `0`、不一致があれば `1` です。

## 中身

`cases.json` に13件。**「検出すべき」と「検出してはならない」の両方**が入っています。

| 群 | 件数 | 何を固定するか |
|---|---:|---|
| 4象限 | 4 | 領域×可視性から重大度が機械的に決まること |
| 検出しないもの | 7 | 広告表現、構造化データ、AI言及、隠れた無害テキスト、本物のレビュー、条件付きCSS、編集部レビュー |
| 断定しないもの | 1 | 外部CSSを解決できないとき hidden と断定しないこと |
| **合計** | **13** | |

**陰性側（検出してはならない）が7件と最多なのは意図的です。**
この基準の実体は「何を検出するか」より「何を検出しないか」にあります。
誤検知は、この種の判定にとって唯一の致命傷です。

## 不一致が出たら

**あなたの実装が誤っているとは限りません。**

不一致は、定義の解釈が割れている箇所を示しています。
`cases.json` の `clause` と `why` に、その条項が何を守ろうとしているかを書いてあります。
読んだうえで納得できなければ、**定義のほうが悪い可能性が高い**ので
[指摘してください](https://github.com/perpensum/agent-directed-manipulation/issues)。

**基準は、変わらないことではなく、変わり方が追えることで信頼されます。**

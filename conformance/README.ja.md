# 適合性テスト — エージェント向け誘導の定義 v0.1

**基準は、誰が測っても同じ判定になって初めて基準になります。**
この一式は、あなたの実装がこの定義と同じ判定に到達するかを確かめるためのものです。

English: [`README.md`](README.md)（こちらが正）

## 使い方

```bash
node run.mjs <あなたの実装のパス>
```

実装は次のいずれかの形の関数を export してください（`default` / `scan` / `scanHtml` のいずれか）。

```js
(html)         => ({ findings: [{ severity: "info" | "warn" | "high" }] })
({ html })     => ({ findings: [{ severity: "info" | "warn" | "high" }] })
```

**どちらでも構いません。** 引数の受け取り方は定義の一部ではないため、
ランナーが両方を試して通ったほうを使います。

**重大度は findings の最大値で比較します。** findings の並び順も定義の一部ではありません。

依存パッケージはありません。Node 18以上で動きます。
終了コードは、全一致で `0`、不一致があれば `1` です。

## 中身

`cases.json` に26件。**「検出すべき」と「検出してはならない」の両方**が入っています。

| 群 | 件数 | 何を固定するか |
|---|---:|---|
| 4象限 | 6 | 領域×可視性から重大度が機械的に決まること |
| 検出しないもの | 17 | 広告表現、構造化データ、AI言及、隠れた無害テキスト、本物のレビュー、条件付きCSS |
| 格上げしないもの | 1 | 編集部レビューが `first_party` に留まり `high` にならないこと |
| 断定しないもの | 2 | 外部CSSを解決できないとき hidden と断定しないこと |
| **合計** | **26** | |

**26件のうち20件が「何も検出しない」ことを期待します。この偏りは意図的です。**
この基準の実体は「何を検出するか」より「何を検出しないか」にあります。
誤検知は、この種の判定にとって唯一の致命傷です。

### 英日の両方を検査します

各ケースは `lang` を持ち、ランナーが言語別の内訳を出します。

```
Definition v0.1 conformance: 26 / 26 agree (call form: scan(html))
  by language: ja 8/8  en 16/16  ja+en 1/1  n/a 1/1
```

**第1版は、いくつかの規則を日本語でしか検査していませんでした。**
英語だけの実装は、検査されないまま通るか、自分のせいでない理由で
`quadrant-fp-hidden` に落ちるかのどちらかでした。第2版で英語版を補っています。
**定義が英日の両方を対象としている以上、テストもそうあるべきです。**

## 参照実装を同梱しています

[`../reference/scan.mjs`](../reference/scan.mjs) は、依存なしの1ファイルで定義を実装し、
26ケース全てを通ります。不一致が出たら、これと突き合わせてください。

**正本ではありません。** 定義と食い違った場合、バグは参照実装の側にあります。

## 不一致が出たら

**あなたの実装が誤っているとは限りません。**

不一致は、定義の解釈が割れている箇所を示しています。
`cases.json` の `clause` と `why` に、その条項が何を守ろうとしているかを書いてあります。
読んだうえで納得できなければ、**定義のほうが悪い可能性が高い**ので
[指摘してください](https://github.com/perpensum/agent-directed-manipulation/issues)。

**基準は、変わらないことではなく、変わり方が追えることで信頼されます。**
